### 실습 1
- 내가 수정한 부분: 가톨릭대학교 성심교정의 실제 장소인 다솔관, 매머드커피, 니콜스관 3곳으로 HTML 내용을 구성하고, 각 장소에 맞는 사진, 설명, 그리고 네이버 지도 링크를 연동함. 모바일 화면에서 사용할 수 있는 햄버거 메뉴 및 반응형 내비게이션 구조를 추가함.
- 버튼 클릭 → 내용 변경 → 지도 변경의 흐름: 데스크탑 버튼이나 모바일 메뉴 링크를 클릭하면 `showPlace(id)` 함수가 실행됨. 이 함수는 모든 장소 패널을 순회하며 선택된 ID와 일치하는 패널만 화면에 보이게(`display: block`) 하고 나머지는 숨기며(`display: none`), 동시에 하단 사진 출처 박스의 `href` 속성값을 선택된 장소의 고유 네이버 지도 링크로 변경함.
- 휴대전화에서 확인한 결과: 모바일 화면에서도 상단 햄버거 메뉴를 통해 장소를 부드럽게 전환할 수 있었으며, 버튼을 누를 때마다 해당 장소의 사진, 설명, 하단 네이버 지도 링크가 올바르게 연동되어 정상 작동함을 확인함.

### 실습 2
- 데이터 출처 URL / 내려받은 날짜: 
  - 카페 데이터: [소상공인시장진흥공단 상가(상권)정보](https://www.data.go.kr/data/15155666/standard.do) / 다운로드 날짜 기입
  - 기상 데이터: [기상청 기상자료개방포털](https://data.kma.go.kr/data/weatherIssue/slthtList.do?pgmNo=690) / 다운로드 날짜 기입
- 데이터 선택 이유 / 대상·기간·단위: 주변 프랜차이즈 카페 분포 현황과 기온 추이를 비교 분석하기 위해 부천시 상권 데이터와 기상청 기온 데이터를 선택함. 대상은 주요 프랜차이즈 카페 점포 수 및 일별 평균 기온이며, 단위는 각각 '개'와 '°C'임.
- 그래프 1: 질문 / 사용한 열 / 그래프 형식과 선택 이유 / 해석: 
  - 질문: 부천시 내 주요 프랜차이즈 카페의 분포 비율은 어떠한가?
  - 사용한 열: `사업장명`
  - 그래프 형식과 선택 이유: 막대 그래프(Bar Chart) — 브랜드별 점포 수를 직관적으로 비교하기에 가장 적합함.
  - 해석: 메가커피, 컴포즈, 이디야 등 주요 브랜드와 기타(개인 카페 등)의 점포 수를 비교하여 시장 경쟁 구도를 파악할 수 있음.
- 그래프 2: 질문 / 사용한 열 / 그래프 형식과 선택 이유 / 해석: 
  - 질문: 시간에 따른 기온의 변화 추이는 어떻게 나타나는가?
  - 사용한 열: `일시`, `평균기온`
  - 그래프 형식과 선택 이유: 꺾은선 그래프(Line Chart) — 날짜별 기온의 연속적인 흐름과 증감 추세를 한눈에 파악하기에 적합함.
  - 해석: 날짜가 지남에 따라 기온이 오르고 내리는 시계열 흐름을 명확하게 확인할 수 있음.
- 필터링·집계·결측치 처리: `PapaParse`를 이용해 CSV를 파싱하고 `header: true`로 열 이름을 객체 키로 활용함. 카페 데이터는 `사업장명` 키워드 포함 여부로 브랜드별 점포 수를 누적 집계했고, 기상 데이터는 `일시`별로 `평균기온`을 합산해 일별 평균을 계산함. 유효하지 않은 데이터나 빈 값은 조건문으로 필터링함.
- 두 탭 전환 방식: 업로드된 CSV 파일의 열 이름(`사업장명` 또는 `일시`/`평균기온`)을 자동 감지하여, 카페 데이터는 막대 그래프와 시장 전망 문구를, 기상 데이터는 꺾은선 그래프와 기상 전망 문구를 동적으로 전환하여 출력함.
- 휴대전화에서 두 탭을 확인한 결과: 모바일 환경에서도 파일 선택 버튼이 정상 작동하며, 파일을 업로드했을 때 화면 너비에 맞게 캔버스와 그래프가 반응형으로 깔끔하게 그려짐을 확인함.
- 빈 데이터·잘못된 CSV를 넣었을 때 결과: 지원하지 않는 형식의 CSV나 필수 열이 없는 파일이 입력될 경우, 상태 메시지에 에러 안내 문구가 출력되고 하단 전망 박스가 숨겨지도록 예외 처리가 구현되어 있음.
- Copilot 활용: 
  - 도움받은 작업: PapaParse와 Chart.js 라이브러리를 연동하여 파일 업로드 시 동적으로 데이터를 파싱하고 차트를 그리는 로직 구현.
  - 대표 질문: "CSV 파일의 열 이름을 자동 감지해서 카페 데이터와 기상 데이터를 구분하고 각각 다른 종류의 차트를 그리는 JavaScript 코드를 작성해줘."
  - 직접 수정·검증한 내용: 한글 인코딩 및 파일 구조에 맞춰 열 이름 판별 조건식을 다듬고, 전망 문구와 데이터 출처 링크가 상황에 맞게 출력되도록 UI 텍스트와 스타일을 수정·검증함.

### 실습 3
- 게임 이름 / 아이디어 / 조작과 규칙: 
  - 게임 이름: 네모의 모험 (장애물 피하기)
  - 아이디어: 화면 오른쪽에서 다가오는 장애물을 피해 점프하여 살아남는 클래식 횡스크롤 미니 게임.
  - 조작과 규칙: 장애물과 충돌하면 게임이 오버(`isGameOver = true`)되며, 장애물을 피할 때마다 10점씩 점수가 누적됨. 스페이스바를 누르면 재시작 가능.
- Copilot에게 보낸 첫 질문: "HTML5 Canvas와 JavaScript를 이용해 스페이스바나 위 화살표 키로 점프하고 다가오는 장애물을 피하는 간단한 2D 플랫포머 미니 게임 코드를 작성해줘."
- 추가 수정 요청과 개선한 점: 모바일 환경에서도 터치로 쉽게 조작할 수 있도록 화면 하단에 별도의 점프 버튼과 반응형 레이아웃을 추가.
- 직접 확인한 동작: 조작 / 점수 / 종료 / 재시작: 
  - 조작: 키보드(스페이스바, ↑)와 모바일 터치 버튼 모두 정상적으로 점프 동작이 실행됨.
  - 점수: 장애물이 화면 왼쪽 끝을 벗어날 때마다 점수가 10점씩 정상적으로 누적됨.
  - 종료: 플레이어와 장애물이 겹칠 때 게임 루프가 멈추며 종료됨.
  - 재시작: 게임 오버 상태에서 스페이스바나 화면 버튼을 누르면 초기화 후 게임이 다시 시작됨.
- 휴대전화에서 확인한 결과: 모바일 화면 너비에 맞춰 캔버스와 컨트롤 버튼들이 깔끔하게 반응형으로 배치되었으며, 터치 버튼을 눌렀을 때 지연 없이 부드럽게 점프 동작이 수행되는 것을 확인함.
- 이미지·소리 출처와 이용 조건(사용한 경우): 외부 이미지나 사운드를 사용하지 않고, HTML5 Canvas API의 도형 그리기를 통해 구현함.

### 저장 설계
- sessionStorage에 저장한 값과 이유: 현재 진행 중인 퀴즈의 응답 상태와 현재 문항 번호 (`week5.teamchem.draft`). 새로고침이나 같은 탭 내 페이지 이동 시 작성 중인 답변이 유실되지 않도록 임시 보관하기 위함.
- localStorage에 저장한 값과 이유: 완료된 퀴즈의 결과 기록 목록 (`week5.teamchem.history`, 최대 20개). 브라우저를 닫거나 나중에 재방문하더라도 이전 참여 기록과 친구 비교 데이터가 유지되도록 하기 위함.
- 내 데이터 조회·개별 삭제·전체 삭제 동작:
  - 조회: '내 저장 데이터 보기' 버튼을 통해 `sessionStorage`의 임시 답변과 `localStorage`의 완료 기록을 화면에 불러옴.
  - 개별 삭제: 완료 기록 중 특정 카드에 있는 '이 기록 삭제' 버튼을 눌러 해당 항목만 배열에서 필터링 후 `localStorage`에 다시 저장.
  - 전체 삭제: '진행 중인 답변 삭제' 및 '게임 데이터 전체 삭제' 버튼을 통해 각 저장소의 키(`draft`, `history`)를 완전히 제거하고 초기 화면으로 복귀.

- 새로고침 / 독립적인 새 탭 / 탭 닫기 비교: 
  - 새로고침: `sessionStorage`에 저장된 임시 답변과 `localStorage`의 완료 기록 모두 유지됨.
  - 독립적인 새 탭: `localStorage`는 공유되나, 탭별 세션인 `sessionStorage`는 독립적으로 유지되어 진행 중인 답변이 공유되지 않음.
  - 탭 닫기: `sessionStorage`는 소멸되지만 `localStorage`에 저장된 완료 기록은 유지됨.
- 중복 저장 / 잘못된 데이터 / 삭제 후 재방문 확인: 유효성 검증 함수(`validBase`, `validAnswers`)를 거쳐 잘못된 형식의 데이터나 변조된 값이 들어올 경우 자동 차단 및 초기화되도록 처리됨.
- 브라우저 저장값을 신뢰할 수 없는 이유: 사용자가 개발자 도구 등을 통해 임의로 값을 수정하거나 삭제할 수 있으며, 다른 사람이 같은 브라우저를 사용할 경우 데이터가 노출되거나 오염될 수 있기 때문.
- 적용한 방어 방법: 데이터 로드 시 버전 확인(`VERSION`), 타입 및 구조 유효성 검증 로직을 포함하여 비정상적인 데이터가 발생할 경우 예외 처리를 수행함.
